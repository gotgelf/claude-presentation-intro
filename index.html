Automation

Hooks — Automate Everything

Shell commands that run automatically at key points in Claude's lifecycle.

What They Do

Deterministic actions that always happen — not relying on Claude to choose. Format code after edits, block protected files, send notifications, validate commands.

Key Events

PreToolUse (block/allow), PostToolUse (react to changes), Stop (verify completion), Notification (desktop alerts), SessionStart (inject context).

Three Types

command — run a shell script. prompt — LLM yes/no judgment. agent — subagent that reads files and runs tools to verify.

# settings.json — auto-format after edits
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "jq -r
          '.tool_input.file_path'
          | xargs prettier --write"
      }]
    }]
  }
}
Configure in ~/.claude/settings.json (global) or .claude/settings.json (project). Run /hooks to browse. · Full docs →
Integrations

MCP — Connect Your Tools

Model Context Protocol lets Claude work with external services directly.

Figma

Read designs, inspect components, extract styles. Build UI directly from Figma mocks without manual spec translation.

Shortcut

Read stories, create tasks, update status. Link code changes to tickets and automate project tracking.

Slack

Read channels, search messages, send updates. Stay connected with your team without leaving the terminal.

# Add an MCP server
$ claude mcp add figma \
  --transport http \
  https://figma.com/mcp

$ claude mcp add shortcut \
  --transport http \
  https://shortcut.com/mcp

# Or configure in .mcp.json
{
  "mcpServers": {
    "slack": {
      "type": "http",
      "url": "https://slack.com/mcp"
    }
  }
}

Deep Dive

Building Custom Skills

Teach Claude new capabilities with a single markdown file.

SKILL.md

Entry point for every skill. YAML frontmatter controls behavior, markdown body has the instructions Claude follows.

Where They Live

Project: .claude/skills/ (shared via git). Personal: ~/.claude/skills/ (all your projects).

Key Options

disable-model-invocation for manual-only. context: fork for subagent. paths to scope to files. allowed-tools to restrict access.

# .claude/skills/deploy/SKILL.md
---
name: deploy
description: Deploy to staging
disable-model-invocation: true
allowed-tools: Bash(npm *)
---

Deploy $ARGUMENTS to staging:

1. Run the test suite
2. Build the application
3. Push to deployment target
4. Verify health checks pass

# Dynamic context injection
# Shell runs before prompt
Branch: !`git branch --show`
Commit: !`git log -1 --oneline`

Built-in Agents

Custom Agents

Define in .claude/agents/. Set model, tools, permissions, hooks, memory, and MCP servers.

Why Use Them

Keep exploration out of your main context. Isolate verbose output (tests, logs). Enforce tool restrictions. Run parallel research independently.

Experimental

Agent Teams — Coordinated Collaboration

Multiple Claude instances working together with shared tasks and direct messaging.

Team Lead
➜
Security reviewer
Performance reviewer
Test coverage reviewer
↔
Shared Task List

How It Differs

Unlike subagents, teammates message each other directly, share a task list, and self-coordinate. Each is a full independent Claude session.

Best For

Parallel code review, competing hypotheses debugging, cross-layer changes (frontend + backend + tests), research from multiple angles.

Good to Know

Experimental feature. Higher token cost (each teammate has own context). Start with 3-5 teammates. Avoid same-file edits across teammates.

Enable with CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 in settings. · Full docs →
Distribution

Plugins — Package & Share

Bundle skills, agents, hooks, MCP, and LSP into installable, versioned packages.

Plugin Structure

A directory with a manifest and any combination of components. Skills are namespaced: /plugin:skill.

Official Marketplace

Built-in catalog with ready-to-use plugins: github, figma, slack, linear, sentry, typescript-lsp, commit-commands, and more.

Standalone → Plugin

Start with .claude/ for quick iteration. Convert to a plugin when you are ready to share with the team or community.

# Plugin directory structure
my-plugin/
  .claude-plugin/
    plugin.json    # manifest
  skills/          # SKILL.md files
  agents/          # agent definitions
  hooks/           # hooks.json
  .mcp.json        # MCP servers
  .lsp.json        # LSP servers

# Install from marketplace
> /plugin install github@claude-plugins-official

# Test locally during development
$ claude --plugin-dir ./my-plugin

# Browse & manage
> /plugin          # open plugin manager
> /reload-plugins  # hot-reload changes

Beta

Browser Automation with Chrome

Build your code, then test and debug in the browser without switching contexts.

How It Works

Claude in Chrome extension connects via MCP. Opens new tabs, shares your login state. Start with claude --chrome or @browser in VS Code.

What You Can Do

Test web apps, read console errors, fill forms, extract data, draft in Google Docs, automate multi-site workflows, record GIFs.

Authenticated Access

Works with any site you're logged into — Gmail, Notion, Jira, your CRM. No API keys or OAuth setup needed.
